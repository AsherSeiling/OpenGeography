## Q3 (2026-10-28)
- **U-5 cause and fix:** the dock's active-panel handler closed the open layout whenever a non-layout panel (Properties, Contents) became active, which cleared the selection and dropped edits. Decision: a layout stays open until another layout tab is activated or its own tab is closed (`followActivePanel`, `layoutPanelClosed` in `layout/actions.ts`). Rejected: keeping `open(null)` and making the Properties pane remember its layout (edits would still have no document to land in; the Layout ribbon tab would flicker); making `update` write to `docs[layout]` for a non-open layout (hides the real fault, and undo history is per open layout).
- **D-1 guard before tiling:** one download is refused when it is wider than 6° (one UTM zone), beyond 84° latitude, or would need cells coarser than 90 m; coarsening below that is allowed but stated in the progress message. The rest of Q3's DEM list (service limits read from the service, mock-server failure tests, cancel during the wait, the dialog hint and 500 MB confirm) moves to D0 with the tiling, since all of it needs the injectable service URL. Rejected: raising the limits without measuring the 3DEP service (DEM-0 needs the network); tiling now (it is D0, the policy for wide areas needs the R0 CRS review).
- **Test-plan IDs:** the full test plan's DEM-01…06 became DEMF-01…06 so they cannot be confused with `TEST_PLAN.md`'s DEM-n.

## Phase R — R0 review of `CRS_PLAN.md` §3 (2026-10-28, lead developer)
Accepted as written: RD-1 (reference hierarchy; never the engine's own output), RD-3 (record `{from, to, operation, accuracy}`), RD-4 (tolerance table, kept in one file), RD-5 (metamorphic zoo harness), RD-6 (out-of-domain is counted, never an empty geometry), RD-7 (GeoJSON export reprojects to EPSG:4326 and says so; an option keeps the layer CRS), RD-9 (distance parameters name their unit; "CRS units" is refused for geographic input). Choices the plan left open:
- **RD-2:** `crs::same` ignores names, remarks and axis order, and treats WGS 84 realisations and datum ensembles as EPSG:4326 (PROJ's equivalence with ensembles ignored). Datum, projection parameters and units always count.
- **RD-8:** Z is carried through unchanged and the result says "vertical datum not transformed"; M is dropped with a message. Refusing was rejected: it would block ordinary 3D shapefiles.
- **RD-10 clipping method (decided here so R8 can start):** world-mode display tables densify every edge (about one vertex per degree) before transforming, cut polygons at the CRS's cut meridian (`lon_0 ± 180°`) in geographic space first, then transform with PROJ per vertex; vertices PROJ cannot project are counted (RD-6). GDAL's wrap-dateline geometry option is used for the cut if it behaves, else the cut is done in SQL with `ST_Intersection` against two half-world boxes. Reason: the cut must happen before projecting, and a conic's apex and infinite edge are handled by clamping latitude to the stated limit.
- **Reference values:** generated by `scripts/gen_crs_reference.py` from `cs2cs` (PROJ 9.8.1 locally). A different PROJ in CI can move a datum-shift answer by millimetres; the test logs both versions and the tolerance table (1 mm / 1e-8°) is the single place to loosen, with a written reason.
- **Order inside Phase R:** R1, R2, R3, R4, R5, R6, R8, R7 as the plan says, with R7's cross-platform run deferred to the final CI push (user, 2026-10-28: no CI until all phases are complete).

## Phase R — R5 rasters and pole-safe queries (built 2026-10-28)
- **Terrain on geographic rasters:** gdaldem has one `-s` scale for both axes, so degrees can't be handled exactly. Hillshade, slope and aspect compute on a copy whose geotransform is in metres at the raster's centre latitude (longitude scaled by cos φ, latitude by the meridian arc), then the result gets the degrees georeferencing back. Exact at the centre latitude; for a DEM spanning several degrees of latitude the error grows (about 1 % per degree at 45°): say so in the help when needed. Rotated geographic rasters are refused with a message. Rejected: warping every geographic DEM to UTM first (changes the user's CRS and resamples twice).
- **Pole-safe identify/select (P18):** when the layer has a display table in the map CRS, identify and rectangle select query it in map coordinates; otherwise the Web Mercator path stays (it is exact below ±85°).
- **Raster CRS fidelity:** an EPSG label counts only if the definition really is that CRS; import writes the definition itself otherwise. All-NoData rasters import with a warning.
- **Not done in R5:** render_extent/vector alignment (R-G7) waits for M4 (on hold); rotated-raster warp and clip tests, contours/polygonize CRS carry.

## Phase R — R4 tool matrix (built 2026-10-28)
- **Metamorphic harness** (`tests/crs_matrix.rs`): 33 recipes cover every vector tool; each runs on the same shapes stored in 8 zoo CRSs (WGS 84 and NAD83 geographic, two UTM zones' datums, Albers, Texas Central in ftUS and metres, Web Mercator) and must give the same feature count, the same total geodesic area (1e-4) and length, and keep the first input's CRS. Overlay cuts and triangulations are planar in the storage CRS, so they get 3e-4 / 1e-3 and a written reason. The guard fails when a registered tool is in neither the recipes nor the exclusion list (tables, raster tools for R5, sinks, each with a reason). Takes about a minute.
- **Fixed by the matrix:** C-6 (triangulations and hulls compute in the local UTM zone for geographic layers) and C-2 (non-finite reprojection results become null geometries; Project counts and names what it leaves out).
- **Closed as a definition:** C-3 (a world box on ±180°/±90° has zero geodesic area; the Earth is two lunes).
- **Unit rule (RD-9):** the tools already name their distance unit (`units` enums on buffer, simplify, near, fishnet, …), so no spec changes were needed; Voronoi's buffer is a percentage of the extent.

## Phase R — R3 transform quality (built 2026-10-28)
- **Root cause of C-1:** DuckDB Spatial carries its own PROJ, which without a data folder uses a small built-in database: NAD83 ↔ WGS 84 became "no change". `Engine::new` calls `resources::ensure_proj_data()`: unless `PROJ_DATA`/`PROJ_LIB` is already set (the installed app, a test), it hands DuckDB the folder GDAL's PROJ searches. Reason: one data folder for both, no new dependency.
- **Datum check instead of an accuracy record:** RD-3 asked for `{operation, accuracy}` per transform. GDAL's API doesn't expose the chosen operation or its accuracy and the PROJ C API isn't linked, so: a known-answer check (`crs::datum_data_report`: NAD27 → NAD83, WGS 84 → NAD83, WGS 84 → NAD27 at 35.2 N, 97.5 W, half a metre) runs at start-up (error pop-up with the fix) and in `--self-test`; tool results name a datum change ("Datum change NAD27 → NAD83: PROJ's best available operation was used, typically 0.1–4 m"). A per-operation accuracy figure waits for F1 or a move of transforms to libproj (C-1b).
- **RD-8 changed:** Z **and M** are carried through a horizontal transform unchanged (measured: DuckDB keeps both). Dropping M would lose data for nothing. Vertical datums are still not transformed.
- **RD-7 built:** exporting a non-WGS 84 layer to GeoJSON reprojects to WGS 84 and says so; "Keep the layer's coordinate system" writes the older `crs` member.

## Phase R — R2 identity and parsing (built 2026-10-28)
- **`crs::key` and `crs::same`:** the key hashes a canonical PROJJSON with names, ids, remarks, usages and axis order left out and units replaced by their size; datum, ellipsoid, prime meridian and the projection method and parameters stay. WGS 84 realisations and datum ensembles are one datum (RD-2), as is an ensemble of any datum (ETRS89). Four spellings of NAD83 / UTM 15N (EPSG code, URN, ESRI `.prj`, PROJ string) and of WGS 84 give one key.
- **Custom datums stay different:** a PROJ string with `+ellps` and `+towgs84` instead of a datum is a custom datum to PROJ, so it is not "the same" as WGS 84 or NAD83, even with a null shift. Reason: calling it the same could hide a real shift; the cost of being "different" is one harmless reprojection.
- **Display keys:** the map's per-CRS display tables now use the same canonical key, so an EPSG CRS and its ESRI twin share a table.
- **Messages:** a definition shown in an error is cut to 80 characters.
- **Importers:** GeoPackage "Undefined … SRS" is "no CRS" (C-4); a CSV with a latitude beyond ±90 warns (C-5). The CSV guess of WGS 84 for lon/lat columns stays, with its existing warning.

## C3.2 Map series (built 2026-10-28)
- **Series in the render request:** `RenderRequest.seriesPage` makes the engine apply page *k* before drawing (frames moved, `{page_*}` tokens set), so the Layout view's preview, a single-page export and the series export all draw the same way. `Layout.series` is JSON in camelCase (`indexLayer`, `nameField`, `sortField`, `extent` "fit" | "fixed_scale", `marginPct`, `scale`); the plan wrote snake_case, camelCase matches the rest of the UI. A frame follows the series with `followsSeries: true`.
- **Fit:** the smallest whole-number scale at which the frame shows the feature plus `marginPct` on each side, checked against the real frame extent (geographic frames aren't exactly linear). A point or an empty extent uses the series scale, else 1:10 000.
- **All or nothing:** a PDF is assembled from every page (`svg2pdf::to_chunk` pages joined with `pdf-writer`, added as a direct dependency; it was already in the graph) and written once, atomically; PNG pages go to a hidden staging folder and are renamed together at the end. Cancel is checked between pages and inside each render; progress counts pages. At most 500 pages.
- **Not built:** greying out the other index features ("highlight current page", optional in the plan); SVG for a series; a page list on the Layout view beyond stepping.

## C3.0 Layout polish (built 2026-10-28)
- **Tile cache:** GDAL's WMS `<Cache>` in a per-user folder from `resources::tile_cache_dir()` (macOS `~/Library/Caches`, Windows `%LOCALAPPDATA%`, Linux XDG cache; `GIS_STUDIO_CACHE` overrides), tiles kept 30 days. Only tiles a preview needs are fetched, as the USGS policy allows; there is no prefetching. OpenStreetMap stays out of print.
- **Arrange:** the element array order is the stacking order. Align uses the common box of two or more elements, or the page margins for one; locked elements never move; rotation is ignored (the unrotated box is used).
- **dpi box:** one session-wide value (72–600, remembered in the browser or webview storage), used by the PNG and PDF exports. Map images are still capped at 300 dpi.
- **Scale bar ratio:** a separate line under the distances, so it never collides with them; the bar needs about 4 mm more height (the engine warns when too short).
- **Rulers:** millimetres from the page corner, SVG, measured from the page's position in the scroll area.

## L3 label edits in layouts (2026-10-28)
- **Storage:** `labelOverrides` on the map frame (`{ layerId: { style?, features: { fid: { dxMm, dyMm, rotation, text, sizePt, hidden } } } }`), camelCase like the rest of the UI, keyed by the stable `__fid`. One frame `update` per edit, so undo and redo come free. The plan wrote `dx_mm`; camelCase was used to match `LabelStyle` and the TypeScript types.
- **Pinned = placed first, never dropped:** any of move, rotation, text or size pins a label. Pinned labels are placed before every automatic one (across layers) wherever the user put them, even off the frame; automatic labels avoid them. A hidden label is not drawn and never comes back on its own; it is still returned (`hidden`) so the UI can show a dotted box and Reset it.
- **The preview returns the placed labels** (`LayoutPreview.labels`, `droppedLabelEdits`) so no new command was needed: devserver and Tauri already pass the preview through. Hit boxes show only when no render is in flight.
- **Deviation from the plan:** rotation is a number in Properties (and the automatic angle for lines), not a drag handle. Reason: smallest change that meets L3-P1…P6; a handle can be added later on the hit box. Not hidden from the user: listed in TEST_PLAN 9.16o.
- **Dropped edits:** the engine ignores an edit whose feature is gone (checked against the layer table, so a feature merely outside the frame keeps its edit) and warns; the UI removes the edit on the next preview.

## L2 labels in layouts (2026-10-28)
- **Anchors from the part inside the frame:** polygon and point labels use `ST_PointOnSurface` of the geometry clipped to the frame, so a big polygon that only partly shows is still labelled (the plan said "clipped to the frame"). Lines: midpoint of the longest part inside the frame, turned to the line, kept right-way-up. Collisions are greedy in draw order, top layer first, on boxes measured with the bundled Noto Sans. A label whose box leaves the frame is skipped and counted. A layer is considered up to 50 000 features per frame; beyond that the frame warns.
- **Halo:** two `<text>` elements (stroked underlay, then fill), not `paint-order`, so every renderer and the PDF export agree.
- **CI cadence (user, 2026-10-28):** CI runs once at the end of the L phase (after L3), not per L task; L2 and L3 are merged locally and pushed together.

## L1 labels (2026-10-28)
- **Anchors through the existing tile route:** polygon label anchors are requested with a pseudo-field `__anchors` in the usual `fields=` list (`tiles::ANCHORS`), not a new route. Reason: the devserver and the `gis://` protocol already forward `fields`, so both stay in parity with no new command, and the engine's tile cache already keys on the field list. An anchor is kept only in the tile whose half-open box contains it, so a polygon cut by tile edges is labelled once. Rejected: a `.lbl` URL suffix (two routes to change and keep in step); labelling the clipped polygons in OpenLayers (duplicates across edges).
- **Labels on their own declutter layer:** OpenLayers decluttering applies to a whole layer, so labels get their own layer above the symbols; symbols are never hidden by labels. The data layer's cache key ignores the label, so editing a label does not reload symbols.
- **Scale limits:** `minScale` = zoomed-in limit, `maxScale` = zoomed-out limit (denominators of 1:N); both optional. The engine mirror stores them as whole numbers.

## Plan decisions (Opus, 2026-10-25)
- **GDAL thread safety before M4:** M4 serves raster tiles from many threads, and the one macOS CI SIGSEGV happened in raster layout tests run in parallel (conda GDAL). Rule: no GDAL `Dataset` or `CoordTransform` crosses threads; each render opens its own handle. Concurrent warps are capped at `available_parallelism`. M4's acceptance adds P17: 64 threads × `render_extent` on the same raster, 20 repeats, on all three CI platforms. If it crashes, warps go behind one process-wide mutex (slower, safe) and the cause is chased separately.
- **Basemap tiles for layout previews:** cache them on disk with GDAL's WMS `<Cache>` element, in the app cache dir from `resources.rs`. That's allowed by USGS (no bulk prefetch, only tiles a preview needs); OSM stays display-only. It fixes the 4–5 s re-fetch on every edit. Part of C3.0.
- **Undo dropping `lastOutput`:** keep each node's last output outside the undo history: a `lastOutputs` map beside the node trees, saved in project.json, not part of zundo state. A small fix (B5).
- **Layout polish before templates (C3.0):** rulers, an Arrange group (bring forward/back, align), a "1:N" label option on the scale bar, a dpi box in Export, plus the basemap cache. Templates (C3.1) need the label and arrange to look right.
- **Bugs:** `docs/BUGS.md` is the bug list. Each merge batch triages it. Fixes go to one Sonnet bug-fix session; Opus reviews any that touch risky areas (geodesy/CRS, transactions, licensing).
- **Errors:** UI code reports failures through the error store (`ui/src/errors/`), never only to the console or status bar. Each pane has its own error boundary. Engine errors return readable messages.
- **Slow cancel (B-T4):** split long single-call geometry work into batches the interrupt watcher can stop between. Geodesic Buffer runs in chunks of about 50k features. Dissolve does a partitioned union (a coarse grid of spatial tiles, then a final union of the per-tile results). Target: Cancel stops within 2 s on the B-T4 fixtures. Results must equal today's output (tests compare them).
- **Slow cancel, as built (B-T4):** the plan's 50 k-feature chunks were tried and dropped: each statement pays about 1.5 s of PROJ setup, so 30 chunks took 126 s against 27 s for one query. The real cause was PROJ setup contention (see `nodes/batching.rs`), fixed by sorting the layer by projection centre before buffering. Output rows keep the layer's order. Dissolve uses tiles plus pairwise unions as planned (a flat final `ST_Union_Agg` still blocked Cancel for ~5 s).
- **Feature labels moved forward (L1, L2):** the user needs labels now, so they come before C3.0 instead of with C4. Each layer has one label definition in `LayerStyle.label`, shared by the map view and layouts. OpenLayers draws map labels and hides overlaps (declutter). Polygon labels come from engine anchor points (`ST_PointOnSurface`), so a polygon split across tiles is labelled once. Layouts use greedy page-space collision and report skipped labels. L3 (user request) adds editing inside the layout: per-layout style overrides, and per-label move, rotate, text, hide and reset, stored in the layout document by `__fid`. Edited labels are pinned and placed first. Details: `LAYOUTS_PLAN.md` L1–L3.
- **M4 on hold** at the user's request (2026-10-25).
- **B6 Split by attribute (user request, 2026-10-25):**
  - **Where:** layer context menu and Data tab → "Split by Attribute…". The engine command `split_by_attribute(layer, field, target)` also goes in the devserver and `api.ts`.
  - **Targets:** `layers` (one new project layer per value) or `files` (a folder, format GeoPackage or shapefile, one file per value).
  - **Groups:** one per distinct value, NULL as "(no value)". Names are the value made safe for filenames, with a `_2` suffix on clashes.
  - **Limits and safety:**
    - A confirm step above 200 outputs, and a hard cap of 1,000.
    - Never writes onto any layer's source file (same check as Export).
    - `progress::Task` per output, with Cancel between outputs.
    - Each output keeps the input's CRS and its sources (citations).
    - Reports the counts per output and any rows skipped.
  - **Credit:** cite QGIS `native:splitvectorlayer`.
  - **Tests:** engine tests (groups, NULL, name clashes, cap, CRS and sources kept, cancel) plus e2e.
- **B7 Category precedence (user request, 2026-10-25):**
  - **UI:** categorized styles keep their classes in an ordered list. The symbology pane gets drag handles and "Reverse".
  - **Draw order:** a class higher in the list draws on top. On the map, through `zIndex` per class in the OpenLayers style function. In layouts, the frame renderer sorts features by class order before drawing.
  - **Legend:** follows the same order.

## Map view — `docs/MAP_PROJECTION_PLAN.md`

## Layouts (Phase C) — `docs/LAYOUTS_PLAN.md`
- **2026-10-23 C2.1 renderer core** (`crates/engine/src/layout/`):
  - **Modules:** `model.rs` is the L2 model plus a `LayerStyle` mirror. `geo.rs` holds `Body`, `FrameCrs`, the scale factor k, convergence and extent. `frame.rs` turns a layer into styled SVG paths: DuckDB transform → clip → simplify at 0.1 mm. `svg.rs` does fixed-precision numbers. `export.rs` does PDF (svg2pdf) and PNG (resvg).
  - **Geodesy:** k and convergence use the frame CRS's *own* geographic CS, not WGS 84; a datum step perturbed k by 2.5e-6. The `Body` supplies only the ellipsoid. In non-conformal CRSs, k is the grid-east scale, which is the scale bar's direction.
  - **Styling:** opacity uses `fill-opacity`/`stroke-opacity`, so the PDF has no transparency groups. UI px → mm at 96 dpi. Graduated classes follow MapLibre `step`.
  - **Dependencies:** svg2pdf 0.13, resvg 0.45 (pinned to svg2pdf's usvg), geographiclib-rs 0.2; Opus licence review passed. Noto Sans (OFL) is compiled in; system fonts are never used.
  - **Open item:** the P3 golden SVG SHA must match on Linux/Windows CI (conda PROJ).
- **2026-10-23 C1 design**:
  - The engine renders each page to SVG, then PDF and PNG; MapLibre can't draw a true CRS.
  - Fonts are bundled only. Frames take an explicit CRS.
  - Scale bar and north arrow are geodesic at the frame centre, through a `Body` (Earth only until F1).
  - Layouts are stored in `__layouts`.

## Attribute history (Phase B) — `docs/ATTRIBUTE_HISTORY_PLAN.md`
- **2026-10-23 B2.3 table pane UI** (`ui/src/panes/table/`):
  - **Modes:** node mode is read-only. Diff mode's chips filter the grid. The node card menu has View table and Compare with input.
  - **Saving:** each node's `lastOutput` is saved in project.json. `pruneNodeCache(live, pinned)` runs on save and when a tree is removed.
  - **Lost diffs:** a diff is dropped on close, node switch or compare change. A diff lost to reopen/Save As re-runs once, then shows a prompt; the grid is never blank.
  - **Known gap:** undoing a tree edit can drop `lastOutput`. The node then shows "not run" until the next run, which is a cache hit.
- **2026-10-23 B2.2 diff + node rows** (`history.rs`):
  - **Diff tables:** each call gets a unique `__diff_<a>_<b>_<key>_<n>` table. They're never indexed, and are swept on open and new project.
  - **Paging:** node-row `fids` are row positions. Layer Input views page by `row_number()`.
  - **Speed:** 1M rows × 20 fields key diff: 0.44 s.
- **2026-10-23 B2.1 persisted node cache**:
  - **Index:** `__node_<hash>` tables are indexed in `__node_cache`, written in the CREATE's transaction.
  - **On open:** tables from another `engine_version` (`CARGO_PKG_VERSION+CACHE_FORMAT`), broken ones and orphans are dropped. Bump `graph::CACHE_FORMAT` when a tool's SQL changes meaning.
  - **Pruning:** `prune_node_cache(live, pinned)` drops non-live tables, then applies a 2 GB budget; views count 0 bytes. Raster entries stay session-only.
- **2026-10-23 B1 design**:
  - Snapshots are the cache tables.
  - The diff key is the user's key, else an auto-detected unique key, else a content-hash multiset diff.
  - Geometry is never compared across CRSs.

## Engine and tools
- **2026-10-23 Setting validation:** `nodes::validate_params` rejects non-numeric Number values and Enum values outside the options. Empty means unset.
- **2026-10-23 Overlay tools:**
  - Union and Symmetrical Difference share `union.rs` (`minus_sql`/`overlay_ctes`). Singlepart To Multipart is `collect`.
  - Concave hull is a shape in Minimum Bounding Geometry.
  - Delaunay goes through GDAL/GEOS and is capped at 200k features.
- **2026-10-23 Select By Location** (Map → Selection): shares `nodes::select_by_location::location_test` with the model node. Distance is geodesic.
- **2026-10-23 Model-run cancellation:**
  - A watcher thread calls DuckDB `interrupt()` repeatedly until the run returns, because DuckDB clears the flag at each query start.
  - Result writes (`set_result`, `upsert_layer`) run in one transaction, so a cancelled write keeps the previous result.

- **2026-10-23 Surround elements (C2.3):**
  - **Scale bar:** segment length is the largest 1-2-5 value that fits the element (width − 8 mm); the bar is `ground · k / scale` long, with k = east scale factor at the frame centre (`geo::factors`), so for Albers it is the true east–west distance. The optional "1:N" label is not drawn.
  - **North arrow:** rotation = true-north bearing from grid up (`factors.true_north_deg` = −convergence) + the frame's page rotation, both clockwise. The compass star uses fixed ratios, not sin/cos, so its bytes cannot differ between libms.
  - **Legend:** one row per class (categorized: classes + "Other", the colour the frame gives unmatched features; graduated: "< b0", "b0 – b1", "≥ bn"), a bold heading above a layer's classes. Only layers the frame actually drew (visible, vector or raster, with a CRS) appear, top first. It does not clip: an overflowing legend is drawn and reported ("does not fit its height").
  - **Text widths** come from `ttf-parser` on the bundled Noto Sans (advances, no kerning) for ellipsizing and wrapping. `ttf-parser` was already in the tree through resvg/fontdb (MIT OR Apache-2.0); it is now a direct dependency.
  - **Sources:** `render_svg` takes a `cites: &dyn Fn(&str) -> Vec<String>`; the engine builds it from `sources::list` (layer id → "Author, Title (year)", the title cut at ": " or " — "). Derived layers already carry their inputs' sources. Frames are rendered before the other elements so surround elements can read what each frame drew; a surround element whose frame is hidden is reported and not drawn.
  - **UI:** a new frame also gets a Sources line under it (L6) and the frame is 9.5 mm shorter. Properties show positions to 0.1 mm and CRS coordinates to 0.01 without changing stored values.
- **2026-10-23 Graticule, grid, rasters, basemaps (C2.4):**
  - **Graticule:** meridians and parallels are sampled at 64 points and transformed to the frame CRS, so conics curve; the auto interval is the largest of 30°…0.00001° that gives ≥ 3 lines across the smaller span; more than 200 lines, or a frame over a pole or the antimeridian, is reported and skipped. Labels come from `Body::format_lon/lat`; the grid's labels go to the top/right when a graticule is also on. Vertices are written at 0.001 mm, so lat/lon fidelity is 1e-6° up to 1:50,000 (the P16 test frame); at smaller scales the rounding is coarser than 1e-6° by design.
  - **Grid:** straight lines at multiples of the interval in CRS units; refused for a geographic frame.
  - **Rasters:** `raster::render_extent(info, crs, extent, w_px, h_px)` is the shared renderer (`render_tile` calls it for 3857, bytes unchanged). Layout images are one `<image>` per raster layer at the frame's pixel size for `RenderRequest.raster_dpi` (default and maximum 300; the preview/PNG export pass their dpi, min 72). Hillshade pixel size is Mercator-cos(lat) for 3857, the CRS unit for projected CRSs, degrees × the CRS's ellipsoid for geographic ones.
  - **Basemaps:** `layout/basemap.rs` opens the National Map tile service with GDAL's WMS/TMS driver (level 16, EPSG:3857) and warps the frame area into the frame CRS (RGBA PNG). OSM and unknown ids are refused when the layout is saved (tile policy). A basemap that can't be fetched is a warning, not a failed export. Each drawn basemap is recorded once in the project's sources (`sources::record_once`, key `basemap:<id>`) and cited by the Sources element. `Engine::render_layout_svg_with` lets tests supply the tile source; the one network test is `#[ignore]` (`p18_network_usgs_topo_in_utm`, passes locally).
  - **Cost to know:** a preview with a basemap re-fetches tiles on every edit (4–5 s for one 100 km frame over the network). Revisit with a tile cache if it bites.

- **2026-10-23 Map display in any CRS (M1):**
  - **Key and grid:** `crs_display_info(crs, fallbackExtent?)` returns key = first 12 hex of SHA-256 of the sorted-key PROJJSON (`3857` when that equals EPSG:3857's), the proj4 string, and the grid: Web Mercator = the XYZ grid; geographic = 2:1 degree grid (res0 = 180/256); projected = square around the area of use (64 points per edge, transformed with the CRS's own geographic CS, points PROJ can't project skipped), res0 = side/256, z 0–22, origin top-left. No area of use: the caller's fallback extent + 10 % (folded into the key), else an error; geographic CRSs fall back to the world. A CRS proj4 can't express, or a non-degree angular unit, is an error.
  - **Display table** `__disp_<layer>_<key>` (`__fid`, `__d`, `__x0`, `__y0`, `__sz`, R-tree, overview tables above 50k rows via the shared `layers::build_overview_tables`): the layer's `geom` goes source → lon/lat (EPSG:4326), is clipped there to the area-of-use rectangle (two halves across the antimeridian), kept only as the source's kind of geometry (a polygon touching the edge isn't drawn as a line), then projected. The clip is in lon/lat, not in the source CRS as the plan says, so an area of use that is undefined in a projected source CRS can't fail; the cost is that clip edges are straight in lon/lat. Only vertices are transformed (no densify; DuckDB Spatial has no segmentize), as elsewhere. Non-finite or >5e8 results are dropped and counted. `dropped` = features with geometry minus rows kept.
  - **Transaction:** the table, its index, overviews and the `__disp_index` row are one `atomically` transaction inside `history::cancellable`, so Cancel leaves nothing. The index stores the layer version; a table whose version differs from the layer's is never served. `save_meta` (every layer change) cancels builds from other versions and drops stale tables, best effort; `remove_layer` drops all; project open sweeps stale and orphan tables. Budget: its own 2 GB (`display::BUDGET`), separate from the node-snapshot 2 GB, so the worst case is ~4 GB of caches per project (accepted in Opus review); LRU by `last_used` (touched by `display_status`, not per tile).
  - **Tiles:** `tiles::build_tile` and `build_tile_display` share one `mvt` query (3857 SQL unchanged; a test compares features and size to a copy of the old builder, since the thinned features come out of a GROUP BY in no fixed order). Attributes and the definition query come from a join to the layer table on `__fid`, only when a tile needs them. Route `/tiles/<layer>/<crsKey>/{z}/{x}/{y}`; the old 5-part path still means Web Mercator. A tile whose table isn't built is a 404 (never cached). The key→CRS map is filled by `crs_display_info`, so the UI must call it first.
  - **Commands:** `build_display` starts the cancellable "Projecting <layer> for display" task in a thread and returns the status; `display_status` = { ready, building, dropped, error }. Perf (release, M-series Mac, `p6_one_million_points`): 1M points → display table 3.8 s; dense tiles 3.7 ms (z2) and 2.6 ms (z4) through the overview tables. Not in M1: `basemapOffsetM` (plan R1, M2), raster tiles per CRS (M4).

### R6 — CRS UI core
- `crs_info` is a pure function of the definition (GDAL/PROJJSON; no DuckDB) so the picker can preview while typing; `map_factors` reuses the layout engine's `factors`, so the status bar, scale bar and north arrow show the same k and γ.

- R6b built those: Tissot layer (`tissot_layer`, WGS 84 circles carrying k_east, k_north, area_ratio, convergence; grid points that do not round-trip through the CRS are left out and counted), Coordinate System tab details + `same_crs`, layout tokens `{crs}` (name + code, "Custom CRS" for bare PROJ strings), `{datum}`, `{units}`, picker recents (localStorage, remembered on OK). `area_ratio` is measured from the projected polygon because k along grid east/north is not a principal scale away from the central meridian.

### R8 — World view
- A world view is a CRS id prefixed `world:`; `crs::resolve` strips it, so tools, layouts and transforms see the plain CRS and only `display_info` and the display-table build react. The key includes the window, so the area-of-use tables stay.
- Window: `lon_0 − 180 … lon_0 + 180` (inset 1e-6° so both edges of the cut meridian are seen from the same side), latitude limits by family (Mercator ±85, conic stops short of the opposite pole, polar stereographic +30 past the equator, others ±90) with a stated note. UTM/Transverse Mercator and one-sided projections (ortho, geos, gnom…) have no world view and say so.
- Cutting: each source geometry is intersected with the window and with copies shifted ±360° when the window passes ±180° (DuckDB has `ST_Translate`, no `ST_Segmentize`).
- Densifying: geometries spanning more than 10° are densified to 1° through GDAL (`OGR_G_Segmentize`) before the clip, so a polygon edge along a parallel or pole curves instead of becoming a chord (found by the equal-area test: Antarctica's −90° edge). Smaller features are left as they are.
- Reference lines are ordinary WGS 84 line layers with `kind` (meridian, parallel, equator, tropic, central meridian, standard parallel, outline); the world-mode table draws them, so there is one drawing path.
- The 110m land file (138 kB) is bundled, imported on demand and cited in Sources. The projection builder only produces PROJ strings; the CRS key of a built string is the engine's `crs::key`.
- Deferred: distortion colouring (R-W10, optional), the 1 M-point performance run (R-W11), and a cs2cs check of graticule intersections.

## H1 — Interpolation (2026-10-29)
- One node, "Interpolate Points to Raster", over GDAL's grid algorithms (IDW, linear/TIN, nearest, moving average); cites QGIS `qgis:idwinterpolation` / `qgis:tininterpolation`, no QGIS code.
- The grid starts on a multiple of the cell size (same rule as Rasterize); cell size and radius are in the layer's units; the layer's CRS is carried through. Linear is no data outside the points' hull. Non-point geometries and rows without a number are ignored.
- `raster::new_store_path` now appends a counter: the clock repeated on two threads and gave the same file name (found by the new tests).

## H3 — Spatial statistics (2026-10-29)
- Two nodes in the Analysis tab: Spatial Autocorrelation (global Moran's I, randomisation variance after Cliff & Ord 1981; one-row table) and Hot Spot Analysis (Getis-Ord Gi*, Ord & Getis 1995; adds gi_z, gi_p, hotspot -3…3). Formulas written from the papers, no library code.
- Neighbours are each feature's k nearest by centroid (default 8, ties broken by index, so results repeat); weights are row-standardised (Moran) or binary with self (Gi*). Distance-band weights and permutation p-values are not built; local Moran's I and Geary's C are left for later.
- Geographic layers are refused (distances in degrees mean nothing); the user projects first. Features without a number are left out (Moran's I reports how many); the Gi* columns are empty for them.
- Results are joined back by DuckDB's scan order (`row_number() OVER ()`): tables have no `rowid` once they are views.

## H2 — Ordinary kriging (2026-10-29)
- One node, "Kriging (Ordinary)" (Raster tab): fits a spherical, exponential or Gaussian variogram (or tries all three and keeps the best) by weighted least squares over a candidate grid, or takes the user's nugget, sill and range (all three or none). Each cell is predicted from its 8–32 nearest points (default 12). Output: band 1 prediction, band 2 kriging variance; the fitted model is written to the raster's `VARIOGRAM` metadata item. Equations from Isaaks & Srivastava (1989); no library code (the `kriging` crate is 0.0.1 and was not used).
- Points at the same place are averaged. At most 2000 points (evenly thinned) are used for the variogram; all are used for prediction. Geographic layers are refused. Anisotropy, universal kriging and cross-validation are not built.

## H4 — Hydrology via a bundled WhiteboxTools program (2026-10-29)
- Six nodes (Hydrology category): Fill Depressions, Flow Direction (D8, ESRI codes), Flow Accumulation (D8; cells / catchment area / specific contributing area; optional log), Drainage Basins, Extract Streams (threshold), Watersheds (from outlet points). Each runs the `whitebox_tools` program (MIT, John Lindsay) as a child process (`whitebox.rs`): killed on Cancel, errors passed on in words.
- The program is **built from the pinned release v2.4.0 (commit 28ed01f)** by `scripts/build-whitebox.sh`, called from `stage-resources.sh`, and shipped in `resources/whitebox/` with its licence; it is not committed. `GIS_STUDIO_WHITEBOX` points at another copy. 17.9 MB per platform. THIRD_PARTY_NOTICES lists it.

- Results are checked to sit on the input's grid and get the input's CRS written in (never guessed). WhiteboxTools writes no-data in non-stream cells of Extract Streams. Outlets for Watersheds go through a temporary shapefile after projection into the raster's CRS; place them exactly on a stream cell (snapping is not built).

- Two nodes (Raster tab): Spectral Index (NDVI, NDWI, MNDWI, NBR, NDBI, SAVI; two bands chosen by number; arithmetic through the raster calculator, so no-data and zero denominators become no data) and Unsupervised Classification (K-means; Lloyd with k-means++ seeding, fixed seed, so repeated runs match; bands standardised; clusters fitted on an even sample of up to 50 000 cells, then every cell assigned; classes 1…k ordered by the first band; 0 = no data; centres written to `CLASS_CENTRES`). Formulas from the papers, no library code.
- Not built: EVI (needs three bands; the calculator takes two), supervised classification (needs training areas — a design decision for the user), accuracy assessment, PCA, band-set presets per sensor (band numbers are the user's).
